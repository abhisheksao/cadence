# Implementation Plan: Tests & CI (Spec 005)

**Branch**: `005-tests-ci` | **Date**: 2026-10-16 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/005-tests-ci/spec.md`

## Summary

Establish automated CI and release automation via GitHub Actions, black-box E2E verification with Maestro, test coverage reporting with thresholds, and an automated spec traceability and markdown link verification script. All workflows strictly adhere to local-only builds (no EAS), strict quality gates, and zero `.md` references in source code.

## Technical Context

**Language/Version**: Node 22, TypeScript ~6.0 (strict), Temurin JDK 17, React Native 0.86, Expo SDK 57

**Primary Dependencies**: GitHub Actions (`actions/checkout@v4`, `actions/setup-node@v4`, `actions/setup-java@v4`, `gradle/actions/setup-gradle@v4`, `actions/upload-artifact@v4`, `softprops/action-gh-release@v2`), Maestro CLI (local E2E)

**Storage**: GitHub Actions artifact storage (release APK retention) & GitHub Releases (tagged assets)

**Testing**: Jest (unit/component tests with coverage), Maestro (black-box mobile E2E flows), custom verification script (`scripts/check-spec-links.mjs`)

**Target Platform**: GitHub Actions CI runners (`ubuntu-latest`), local developer environments (macOS/Linux)

**Project Type**: Mobile app CI/CD & Testing Infrastructure

**Performance Goals**: CI execution under 5 minutes with warm Gradle/npm cache; PR checks run without delay; E2E flows execute in under 3 minutes locally

**Constraints**:
- Strictly local build commands (`expo prebuild -p android --no-install` + `./gradlew assembleRelease`); NO EAS Build, Submit, or Update (Principle VI)
- Zero `.md` file references in source code and comments (`src/`)
- 80% line and branch coverage threshold on core logic (`src/engine/`, `src/session/`, `src/modes/`, `src/storage/`)
- Offline & private: no analytics, telemetry, or external cloud reporting

## Constitution Check

*GATE: Must pass before Phase 0 research. Re-check after Phase 1 design.*

- [x] **I. Screen-off reliability**: Background session timing and notification persistence are verified end-to-end via Maestro `background.yaml` (`lockDevice` / `unlockDevice`).
- [x] **II. Duck, never pause**: Existing audio ducking guarantees remain untouched and tested via Jest unit suites.
- [x] **III. Offline & private**: CI and releases package the app with zero analytics, tracking, or network telemetry.
- [x] **IV. Android-first, iOS-ready**: CI builds the Android release APK locally via Gradle; iOS workflows can be added in spec 008 with identical local command patterns.
- [x] **V. CNG**: `android/` and `ios/` remain generated by `expo prebuild` and are not committed to git; CI generates them on the fly.
- [x] **VI. Local builds**: CI executes the exact local commands (`npx expo prebuild -p android` and `./gradlew assembleRelease`); no EAS Build or cloud build services used.
- [x] **VII. Test-first**: All new capabilities (coverage reporting, spec link checker script) have unit tests written first; Maestro flows define acceptance criteria.
- [x] **VIII. Quality gates**: CI enforces strict TypeScript (`tsc --noEmit`), linting (`expo lint`), spec link integrity, and Jest tests with coverage on every PR and push.
- [x] **IX. Traceability**: Automated script (`scripts/check-spec-links.mjs`) verifies that all specs in `specs/` are complete and valid, and enforces zero `.md` references in `src/`.

**Post-design re-check (after Phase 1)**: All gates pass. The design introduces clean declarative GitHub Actions workflows, declarative Maestro flows in `.maestro/`, Jest coverage configuration, and a lightweight node audit script.

## Implementation Approach

Ordered for incremental, test-first delivery:

1. **User Story 4 (P2 - Traceability Script & Code Coverage)**:
   - Write `scripts/check-spec-links.test.mjs` verifying link checking, spec directory validation, and zero `.md` in `src/`.
   - Implement `scripts/check-spec-links.mjs` to pass tests.
   - Configure Jest coverage in `package.json` with 80% thresholds on core logic and add `npm run test:coverage` and `npm run check:specs`.
   - Add `npm run check:specs` to `npm run check`.
2. **User Story 1 (P1 - GitHub Actions CI Pipeline)**:
   - Create `.github/workflows/ci.yml`.
   - Configure quality job: Node 22, npm cache, `npm run check`, `npm run test:coverage`.
   - Configure Android build job: Temurin JDK 17, `setup-gradle` cache, `npx expo prebuild -p android --no-install`, `./gradlew assembleRelease --no-daemon`.
   - Upload APK artifact `cadence-release-apk`.
   - Add concurrency cancellation for superseded PR runs.
3. **User Story 2 (P2 - GitHub Actions Release Pipeline)**:
   - Create `.github/workflows/release.yml` triggering on `v*` tags.
   - Assemble release APK, optionally sign if secrets configured, compute `SHA256SUMS.txt`.
   - Publish GitHub Release via `softprops/action-gh-release@v2`.
4. **User Story 3 (P3 - Maestro E2E Test Suite)**:
   - Create `.maestro/smoke.yaml`, `.maestro/session.yaml`, `.maestro/background.yaml`.
   - Add `npm run test:e2e` to `package.json`.
   - Document prerequisites and usage in `quickstart.md` and `README.md`.
5. **Polish & Verification**:
   - Verify CI and Release YAML syntax.
   - Run `npm run check` and `npm run test:coverage`.
   - Verify zero markdown file references in `src/`.
   - Commit and prepare PR to `develop`.
